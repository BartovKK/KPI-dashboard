# KPI-ведомость: дашборд KPI сотрудников ОП и ОС

Веб-приложение для руководителя и сотрудников. Оно забирает данные из Битрикс24 и 1С, считает KPI по правилам из четырёх регламентов и показывает:

- **общий дашборд руководителя**: фонд KPI и сумма к выплате, матрица «сотрудник × пункт KPI» с процентом выполнения и начислением, тренд за 6 месяцев, список того, что требует внимания (обнуление KPI, нет оценки руководителя);
- **индивидуальный дашборд сотрудника**: сумма к выплате и из каких пунктов она сложилась, выплаты по месяцам, карточка по каждому пункту KPI (факт против нормы по каждому нормативу, темп на сегодня для текущего месяца, источник данных, расшифровка записей, по которым посчитан показатель);
- **форму оценки руководителя**: еженедельная оценка исполнительской дисциплины и качества документации, индивидуальный план валовой прибыли, базовая конверсия прошлого года.

Доступ: руководитель (role = manager) видит всех. Сотрудник видит только свой дашборд, и это проверяет сервер, а не только интерфейс.

## Быстрый запуск (демо-данные)

Запустите `run.bat` (он вызывает `start.ps1`). Если на компьютере нет Python, при первом запуске он сам скачает портативный Python (около 11 МБ) в папку `python\`. Устанавливать ничего не нужно, права администратора не нужны. После запуска браузер откроет http://localhost:8080. Окно с чёрным фоном не закрывайте: пока оно открыто, дашборд работает.

Если Python уже установлен, можно запускать и так: `python manage.py run`. В демо-режиме у всех пользователей пароль `demo`: `boss` — руководитель, `petrov`, `orlova` и другие — сотрудники (см. `config.example.json`).

## Переход на реальные данные

1. Скопируйте `config.example.json` в `config.json` и укажите `"mode": "live"`.
2. Заполните блок `employees`: логин, ФИО, должность (`tender_lead`, `tender`, `pm`, `supply`), `b24_user_id` (ID пользователя в Битрикс24, есть в адресе его профиля) и `onec_manager` (ФИО или GUID ответственного в 1С).
3. Настройте Битрикс24 и 1С (ниже).
4. Удалите `data/kpi.sqlite`, если там остались демо-данные, и выполните:
   ```
   python manage.py check      # проверка подключений
   python manage.py sync       # первая выгрузка
   python manage.py password boss
   python manage.py password petrov   # и так для каждого сотрудника
   python manage.py run
   ```
Сервер обновляет данные сам каждые `sync.interval_minutes` минут. Руководитель может обновить их вручную кнопкой «Обновить данные».

### Битрикс24

Создайте входящий вебхук: «Разработчикам → Другое → Входящий вебхук», права **crm, telephony, tasks, user**. Его адрес укажите в `bitrix24.webhook`.

Что настроить в `config.json → bitrix24`:

| Параметр | Что это | Где взять |
|---|---|---|
| `tender_category_id`, `sales_category_id` | ID воронок тендеров и продаж | `python manage.py check` выводит список воронок |
| `tender_stages.in_work` | стадии, которые означают «прошёл квалификацию В работе» | настройки воронки или `crm.status.list` |
| `tender_stages.price_review` | стадия «рассмотрение ценовых предложений» | то же |
| `tender_stages.submitted` | стадия «заявка подана» | то же |
| `fields.*` | коды пользовательских полей UF_CRM_… | настройки полей карточки |

Поля, которые нужно завести в CRM, если их ещё нет:

- **Сделка (тендер):** плановая себестоимость, фактическая себестоимость.
- **Контакт:** признак «ЛПР» (да/нет). Если его нет, ЛПР определяется по заполненной должности, а должности из `secretary_posts` считаются секретарём.
- **Компания:** «Потребность выявлена» и «Стратегия работы» (нужно для KPI ведущего тендерного специалиста про 7 активных клиентов).
- **Лид:** потребность, бюджет и сроки, ЛПР, платёжеспособность, следующий шаг, дата первого контакта. Лид считается целевым, только если заполнены все поля.

Как считается результативный звонок: исходящий звонок длиной от 2 минут (`min_call_seconds`), собеседник не секретарь, и в течение суток по той же карточке CRM создано следующее дело (встреча, звонок или задача). Для тендерных специалистов дополнительно нужна «информация об ЛПР» (`require_lpr` в `kpi_rules.json`):

- звонок привязан к контакту, и контакт — ЛПР;
- звонок привязан к компании, и у компании в CRM уже есть контакт-ЛПР;
- звонок привязан к лиду, и в лиде заполнено поле ЛПР.

У ПМ регламент ЛПР не требует, поэтому для KPI 4 `require_lpr: false`.

Подтверждение отправки КП (ПМ, KPI 4): исходящее письмо в карточке сделки с вложением, в теме или тексте которого есть одно из слов `kp_email_keywords`. Засчитывается меньшее из двух чисел: КП, загруженные в 1С, и такие письма в Б24. Чтобы брать признак из 1С (поле `confirmed`), поставьте `kp_confirmation: "1c"`.

Встреча должна закрываться в день проведения. Точной даты закрытия дела в REST API нет, поэтому берётся дата последнего изменения дела, и по умолчанию нарушение только показывается справочно. Чтобы не засчитывать такие встречи, поставьте `meeting_same_day_close: true`.

### 1С

Для каждого набора данных в `onec.datasets` укажите источник:

- `http` (рекомендуется) — HTTP-сервис в 1С. Программист 1С публикует сервис `kpi`, который по адресу `БАЗА/hs/kpi/<набор>?date_from=ГГГГ-ММ-ДД&date_to=ГГГГ-ММ-ДД` отдаёт JSON-массив строк с полями из таблицы ниже;
- `odata` — стандартный OData-интерфейс 1С (публикация на веб-сервере, «Администрирование → Настройка стандартного интерфейса OData»). Поля задаются в `map`, пример есть в `config.example.json`;
- `csv` — файл выгрузки (разделитель `;`, первая строка — имена полей из таблицы ниже).

В каждой строке обязательно поле `manager`: ФИО или GUID ответственного, как в `onec_manager`. Даты — `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ`. Признаки — `true/false`, `1/0` или `да/нет`.

| Набор | Для какого KPI | Поля |
|---|---|---|
| `sales` | ПМ, KPI 2 «Валовая прибыль» | `id, manager, dt, doc, client, revenue` (выручка без НДС), `cost` (себестоимость), `signed` (УПД/акт подписан обеими сторонами), `signed_date` (дата подписания второй стороной: по ней документ относится к месяцу; если не передана, берётся `dt`) |
| `kp` | ПМ, KPI 4; тендерный специалист, KPI 2 | `id, manager, dt, client, amount, out_of_tender` (КП вне тендера), `confirmed` (скан исходящего письма приложен) |
| `receivables` | ПМ, KPI 6 | `id, manager, doc, client, ship_date, due_date` (срок оплаты), `paid_date, amount` |
| `guarantees` | тендеры, KPI 6 | `id, manager, kind` (`contract` — обеспечение контракта, `application` — обеспечение заявки), `ref, amount, acts_date` (подписаны финальные акты), `unblock_date` (площадка отменила блокировку), `return_date` (деньги на счёте) |
| `penalties` | тендеры, KPI 6 | `id, manager, dt, amount, reason` |
| `supplier_orders` | снабжение, KPI 1–3 | `id, manager, doc, dt, supplier, lot` (единый лот, если заказ разбит), `amount_novat, planned_date, actual_date` (дата отгрузки по УПД/ТН), `complete, defect, mis_sort, deferred_share` (доля суммы с отсрочкой, 0–1), `deferral_days, kp_count` (число КП), `relevant` (КП соответствуют ТЗ), `evidence` (сканы и сравнительная таблица), `affiliated, single_source, emergency, justified` (утверждённое обоснование закупки без конкурса), `customer_order` |
| `supply_funnel` | снабжение, KPI 5 | `id, manager, dt, customer_order, client, stage` (достигнутый этап: `need`, `search`, `kp`, `contract`, `delivered`) |

## Откуда берётся каждый пункт KPI

| Должность | KPI | Источник | Как считается |
|---|---|---|---|
| Тендерный и ведущий тендерный специалист | 1. Конверсия воронки | Б24, воронка тендеров | выигранные ÷ торги с итогом, прошедшие «В работе» и этап рассмотрения ЦП; цель 10%; показывается и за квартал |
| | 2. Развитие базы и выход на ЛПР | Б24 (звонки, встречи, компании), 1С (КП) | ведущий: касания (30 в сентябре 2026, далее 70), 3 результативных звонка в день, 7 активных клиентов (прошлые месяцы — по снимку на конец месяца); специалист: 3 звонка в день, 3 встречи, 105 КП вне тендера |
| | 3. Операционная дисциплина | Б24 + оценка руководителя | поданные заявки против нормы и качество документации |
| | 4. Экономическая эффективность | Б24 (цена и себестоимость сделки) | средняя маржа выигранных проектов ≥ 10%; победа ниже плановой себестоимости обнуляет весь KPI |
| | 5. Исполнительская дисциплина | оценка руководителя (+ задачи Б24 справочно) | средняя недельная оценка «документооборот» и «задачи» = 100 |
| | 6. Дебиторская задолженность | 1С | среднее время возврата обеспечения контракта, % обеспечений заявок, возвращённых за 1 рабочий день, штрафы = 0 |
| Проектный менеджер | 1. Конверсия | Б24, воронка продаж | успешные ÷ закрытые сделки; цель — базовый уровень прошлого года + 10%, без базы — 7% |
| | 2. Валовая прибыль | 1С | выручка − себестоимость по УПД/актам, подписанным обеими сторонами в этом месяце, против индивидуального плана; `metric: "revenue"` — считать объём выручки |
| | 3. Квалифицированные лиды | Б24 | ≥ 10 лидов в месяц со всеми 5 заполненными критериями |
| | 4. Операционная активность | Б24 + 1С | 15 результативных звонков в день, 15 КП в день (в 1С и письмо в сделке Б24), 5 встреч с протоколом и резюме |
| | 5. Исполнительская дисциплина | оценка руководителя (+ задачи Б24) | как у тендеров |
| | 6. Дебиторская задолженность | 1С | 100% оплат в срок; просрочка больше 14 дней обнуляет весь KPI |
| Специалист снабжения | 1. Своевременные поставки | 1С | просроченных (опоздание, недопоставка, брак, пересортица) не больше 20% |
| | 2. Закупки с отсрочкой | 1С | заказы от 500 000 ₽ без НДС, где ≥ 30% суммы с отсрочкой ≥ 14 дней; цель 80%. Если несколько заказов ниже порога (один лот или один заказ клиента у одного поставщика) в сумме дают ≥ 500 000 ₽, руководитель видит предупреждение о возможном дроблении |
| | 3. Конкурентность | 1С | лоты от 500 000 ₽ (лот собирается из всех заказов и относится к месяцу первого заказа): 3 КП, соответствие ТЗ, доказательства, нет аффилированности; отсутствие конкурса закрывается утверждённым обоснованием, аффилированность — нет; цель 80% |
| | 4. Исполнительская дисциплина | оценка руководителя (+ задачи Б24) | как у тендеров |
| | 5. Конверсия воронки снабжения | 1С | потребность → поставка против целевой конверсии |

Все нормы, веса, оклады и суммы KPI лежат в `kpi_rules.json`. Если регламент изменится, достаточно поправить этот файл и перезапустить сервер.

## Что нужно уточнить в регламентах

Этих чисел в документах нет. Сейчас стоят временные значения, они помечены `_todo` в `kpi_rules.json`:

1. Норма поданных заявок в месяц для тендерного (сейчас 15) и ведущего тендерного специалиста (20).
2. Допустимое среднее время возврата обеспечения контракта (сейчас ≤ 30 дней).
3. Целевая конверсия воронки снабжения (сейчас 70%).
4. Индивидуальный план валовой прибыли ПМ: вводится руководителем в карточке KPI 2. Пока план не введён, используется 1 500 000 ₽.
5. Как платить при частичном выполнении. Сейчас пункт оплачивается полностью при выполнении 100% норматива, иначе 0. Можно включить пропорциональную выплату: `payout.mode = "proportional"`.
6. Что значит «KPI не выплачивается» при просрочке ДЗ больше 14 дней у ПМ. Сейчас обнуляется весь KPI, как и при победе в тендере ниже себестоимости у тендерных специалистов. Если имелся в виду только пункт 6, поставьте `zero_all_if_overdue: false`.
7. «Звонки 3–4 в день» у ведущего тендерного специалиста. Сейчас это 3 результативных звонка в день, и тогда норма 30 касаний в сентябре 2026 ни на что не влияет: 3 × 22 рабочих дня = 66 результативных звонков, а каждый такой звонок одновременно касание. Возможно, имелись в виду любые звонки.
8. Раздел KPI 3 в регламенте ведущего тендерного специалиста пустой. Описание взято из регламента специалиста.
9. «Рост на 10% к среднему прошлого года» у ПМ. Сейчас это относительный рост (база × 1,1), а не +10 процентных пунктов.
10. Периоды «ежеквартально» и «по проекту». Сейчас всё считается и платится помесячно, конверсия за квартал показывается справочно. При небольшом числе торгов конверсия за месяц сильно скачет, а при выплате «всё или ничего» это превращается в лотерею. Возможно, KPI 1 и KPI 4 тендерных специалистов правильнее платить по кварталу.
11. Месяц без данных (нет торгов с итогом, нет побед). Сейчас пункт не выплачивается (`payout.pay_when_no_data: false`).
12. Шкала оценки руководителя. Сейчас 0–100 баллов, пункт выполнен при средней оценке ровно 100.
13. Закупка без конкурса с утверждённым обоснованием («признаётся валидной, не штрафуется»). Сейчас она засчитывается как конкурентная; другой вариант — исключать её из базы расчёта.

## Производственный календарь

Праздники (`holidays`) и рабочие выходные дни (`workdays`) в `config.json` нужно обновлять каждый год: от них зависят нормы «в день» и возврат обеспечений за 1 рабочий день. Еженедельная оценка руководителя относится к месяцу, на который приходится четверг недели, поэтому каждая неделя попадает ровно в один месяц.

## Как запустить на сервере

- Сервер можно поставить на любой компьютер в сети, у которого есть доступ к порталу Битрикс24 и к 1С. Сотрудники открывают `http://ИМЯ-СЕРВЕРА:8080`.
- Чтобы дашборд запускался вместе с Windows: Планировщик заданий → «При запуске компьютера» → `run.bat` (или служба через NSSM).
- Для доступа извне офиса поставьте перед ним обратный прокси с HTTPS (IIS, nginx) и включите `server.secure_cookie`. Пароли хранятся в базе в виде хешей PBKDF2, сессия живёт 12 часов, после 10 неудачных попыток вход с того же адреса под тем же логином блокируется на 15 минут.
- Синхронизация сначала выгружает все данные, а затем записывает их в базу одной транзакцией. Пока идёт запись, дашборд ждёт и не показывает наполовину обновлённые таблицы.
- `config.json` и папка `data/` исключены из git (`.gitignore`): в них адрес вебхука, пароль 1С и хеши паролей.
